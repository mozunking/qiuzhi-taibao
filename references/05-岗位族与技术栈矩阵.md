# 计算机类岗位族与技术栈矩阵

> 用途：拿到一个 JD，先归族，再判断"我够不够、值不值得去"。同一家公司不同岗位族差别远大于不同公司同一岗位族。
> 与 `scripts/qiuzhi.py` 的 `--family` 参数对应；不填时脚本会按族取默认技术栈做比对。

## 一、十个岗位族（应届本科实际能落的位置）

| 岗位族 | 主要工作 | 核心栈 | 本科可投 | 成长性 | 五年后能带走什么 |
|---|---|---|---|---|---|
| 后端/服务端 | 接口、业务逻辑、数据库 | Java/Go/Python、Spring、MySQL、Redis、MQ、Linux | 高 | 0.95 | 分布式系统经验、性能调优 |
| 前端 | 页面、交互、工程化 | JS/TS、Vue/React、CSS、构建工具 | 高 | 0.80 | 可视化、工程化体系 |
| 客户端 | App/桌面端 | Java/Kotlin、Swift、C++、Flutter | 中 | 0.80 | 端上性能、跨端框架 |
| 算法 | 模型训练与部署 | Python、C++、PyTorch、数学 | 低（多要硕士） | 1.00 | 模型能力、论文/竞赛 |
| 数据 | 数仓、ETL、分析 | SQL、Python、Hive、Spark、Flink | 中 | 0.90 | 数据建模、指标体系 |
| 测试/测开 | 自动化、质量体系 | Python、Selenium、接口测试、Linux | 高 | 0.65–0.75 | 自动化框架、质量度量 |
| 运维/SRE | 稳定性、发布、监控 | Linux、Shell、Docker、K8s、网络 | 高 | 0.60–0.65 | 故障处置、容量规划 |
| 嵌入式 | 驱动、固件、车机 | C/C++、单片机、RTOS、Linux 驱动 | 高 | 0.80 | 软硬结合（稀缺） |
| 安全 | 渗透、合规、攻防 | 网络、渗透测试、密码学、Linux | 中 | 0.85 | 攻防实战、证书 |
| 实施/技术支持/解决方案 | 部署、交付、客户沟通 | SQL、Excel、Linux、行业知识 | 高 | 0.45–0.50 | 行业理解、交付管理（转售前/项目经理） |

**给应届生的排序建议**（同样条件下）：后端 ≈ 嵌入式 > 数据 ≈ 安全 > 前端 ≈ 客户端 > 测开 > 运维 > 实施。
不是贬低实施，而是**实施的技术复利最低**——干三年跳槽时，能拿出来的还是"会部署会沟通"，议价能力弱。

## 二、技术栈分层：会在简历上写什么才不算吹

| 层级 | 表述 | 能经得起几层追问 |
|---|---|---|
| 了解 | 看过文档、写过 demo | 一层（是什么） |
| 熟悉 | 项目里用过、踩过坑 | 两层（怎么用、什么坑） |
| 熟练 | 能独立选型、能排障 | 三层（内部机制、边界） |
| 精通 | 能改源码、能做技术决策 | 四层以上（设计取舍、演进） |

**本科生写"精通"基本都会被当场戳破**，写"熟悉/熟练"更安全。

## 三、岗位族的识别信号（看 JD 用词就知道归哪族）

- "高并发、分布式、微服务、中间件" → 后端
- "组件化、性能优化、兼容性、还原设计稿" → 前端
- "内存、帧率、启动优化、端上" → 客户端
- "模型、训练、推理、召回、精排" → 算法
- "数仓、指标、ETL、报表" → 数据
- "自动化、覆盖率、用例、回归" → 测试
- "稳定性、发布、监控、告警、容量" → 运维
- "驱动、固件、协议、板级、RTOS" → 嵌入式
- "渗透、漏洞、等保、应急响应" → 安全
- "驻场、交付、客户培训、验收" → 实施

## 四、跨族切换的成本

| 从 → 到 | 难度 | 补什么 |
|---|---|---|
| 测试 → 后端 | 中 | 补一个完整业务项目 + 数据库设计 |
| 运维 → 后端 | 中 | 补语言与框架，运维背景是加分 |
| 后端 → 算法 | 高 | 需要系统补数学与模型训练，通常靠读研 |
| 实施 → 开发 | 高 | 需要脱产做项目，越晚越难 |
| 任何 → 测开 | 低 | 自动化框架 + 一门脚本语言 |

结论：**第一份工作的岗位族，基本决定了三年的轨道**。所以宁可岗位族好、公司差一点。
